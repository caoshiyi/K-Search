# AscendC 910B 系列硬件架构速查

---

## 1. 芯片概览

| 产品 | AIC 数 | AIV 数 | AIC:AIV | AICore Num |
|:---|:---|:---|:---|:---|
| 910B1 / 910B2 | 24 | 48 | 1:2 | 24 |
| **910B3** | **20** | **40** | **1:2** | **20** |

> 算子开发以 **910B3** 为主。

---

## 2. 分离模式与 SPMD 编程

910B 采用**分离模式**，一个 AI Core = **1 AIC + 2 AIV**，各自有独立 Scalar。

SPMD 模型：所有核运行相同代码，通过 `GetBlockIdx()` 区分数据。分离模式下 blockDim 按算子类型设置：

| 算子类型 | blockDim | 启动方式 |
|:---|:---|:---|
| 纯 Vector | 40（AIV 数） | 每个 AIV 独立执行 |
| 纯 Cube | 20（AIC 数） | 每个 AIC 独立执行 |
| **MIX（融合）** | **20（AIC 数）** | 20 组，每组 1 AIC + 2 AIV |

MIX kernel 中用宏区分代码路径：`ASCEND_IS_AIC` 走矩阵逻辑，`ASCEND_IS_AIV` 走向量逻辑，`vecBlockIdx`（0/1）区分同组的两个 AIV。

## 3. 存储层次与规格

```
┌──────────┐       ┌──────────────────────────────────┐
│          │       │              AIC                 │
│          │       │  ┌────────────────────────────┐  │
│          │─MTE2─→│  │  L1  512KB                 │  │
│          │       │  └──────┬──────────┬──────────┘  │
│          │       │     MTE1↓      MTE1↓             │
│          │       │  ┌──────────┐ ┌──────────┐       │
│          │       │  │ L0A 64KB │ │ L0B 64KB │       │
│  GM      │       │  └────┬─────┘ └────┬─────┘       │
│  64GB    │       │       └─── Cube ────┘            │
│          │       │             ↓                    │
│          │       │  ┌─────────────────────┐         │
│          │←FixP──│  │ L0C 128KB  BT 1KB   │         │
│          │       │  └─────────────────────┘         │
│          │       ├──────────────────────────────────┤
│          │       │             AIV-0                │
│          │─MTE2─→│  ┌────────────┐                  │
│          │       │  │ UB 192KB   │←→ Vector         │
│          │←MTE3──│  └────────────┘                  │
│          │       ├──────────────────────────────────┤
│          │       │             AIV-1                │
│          │─MTE2─→│  ┌────────────┐                  │
│          │       │  │ UB 192KB   │←→ Vector         │
│          │←MTE3──│  └────────────┘                  │
└──────────┘       └──────────────────────────────────┘
```

> 三个核完全独立，仅通过 GM 交换数据。每个 AIV 各自独享自己的 192KB UB。

### 各存储单元详细规格

| 存储单元 | 容量/核 | 归属 | 对齐要求 | 推荐数据格式 |
|:---|:---|:---|:---|:---|
| **Global Memory** | **64 GB** | 所有AIC/AIV 共享 | 512B 对齐性能最优 | ND |
| **L1 Buffer** | **512 KB** | AIC 独享 | 32B | FRACTAL_NZ |
| **L0A Buffer** | **64 KB** | AIC 独享 | 512B | FRACTAL_ZZ |
| **L0B Buffer** | **64 KB** | AIC 独享 | 512B | FRACTAL_ZN |
| **L0C Buffer** | **128 KB** | AIC 独享 | 64B | FRACTAL_NZ |
| **Unified Buffer** | **192 KB** | 每个 AIV 独享 | 32B | 无特殊要求 |

## 4. 搬运通路

| 搬运单元 | 通路 | 说明 |
|:---|:---|:---|
| **MTE2** | GM → {L1, L0A, L0B, UB} | 基于 Cache Line（128/256/512B）搬运性能最优 |
| **MTE1** | L1 → {L0A, L0B} | 按分形大小搬运 |
| **FixPipe** | L0C → GM | 可随路完成量化/反量化/ReLU/格式转换 |
| **MTE3** | UB → GM | — |

### 典型数据流

**Cube 计算流：**
```
GM →(MTE2)→ L1(NZ) →(MTE1)→ L0A(ZZ) / L0B(ZN) →(Cube)→ L0C(NZ) →(FixPipe)→ GM
```

**Vector 计算流：**
```
GM →(MTE2)→ UB →(Vector)→ UB →(MTE3)→ GM
```

## 5. 数据排布格式与分形大小

### 5.1 矩阵乘相关格式

| 格式 | 所在位置 | 用途 | 分形形状 |
|:---|:---|:---|:---|
| FRACTAL_ZZ (ZZ) | L0A | Cube 左矩阵输入 | M0 × K0 |
| FRACTAL_ZN (ZN) | L0B | Cube 右矩阵输入 | K0 × N0 |
| FRACTAL_NZ (NZ) | L0C、L1 | Cube 输出 / L1 缓存 | N0 × M0 |

### 5.2 分形大小与数据类型对应表

| 数据类型位宽 | M0 | K0/N0/M0/N0 | 单个分形大小 |
|:---|:---|:---|:---|
| 4 bit (int4) | 16 | 64 | 512B |
| 8 bit (int8/uint8) | 16 | 32 | 512B |
| **16 bit (half/bfloat16)** | **16** | **16** | **512B** |
| 32 bit (float/int32) | 16 | 8 | 512B |

> Cube 计算以 16×16（half）为基本单元。float 算力为 half 的 1/4。

### 5.3 L0C 与 L1 的 NZ 分形差异

- **L0C 中的 NZ**：分形形状 16×16，包含 256 个元素
- **L1 中的 NZ**：分形形状 16 × (32B / sizeof(Datatype))，大小 512B
- 从 L0C 搬运到 L1 时，分形大小可能发生变化（通过 Fixpipe 的 Channel merge/split 实现）

### 5.4 L1 → L0A/L0B 的格式转换

```
L1 (NZ) ──MTE1──→ L0A (ZZ)
L1 (NZ) ──MTE1──→ L0B (ZN)
```
L1 采用 NZ 格式可以降低搬运时的格式转换开销。

### 5.5 UB 数据格式

UB 对数据格式无特殊要求，通常使用 ND 格式。Vector 指令首地址和操作长度要求 32B 对齐。
