# 第一轮经验教训复盘（lessons_round1.md）

> 实验范式：设计 subagent（可参考 main HEAD）写设计文档 → 实现 subagent（禁看 main）仅凭文档盲实现 → 主控复核性能 → 无收益则循环。
> 本文复盘第一轮，并把改进点反向沉淀给下一轮。

## 0. 本轮目标与结果（一句话）
在基线 66a35f8（单级 128 微块，2391us）上**独立**落地「QKV 双向两级分块 + L1 大块复用」单一优化点，盲实现一次编过、精度 PASS，性能 **2391us → 1590us（1.49x）**，并纠正了「两级分块单独无收益」的历史误判。

## 1. 关键认知修正（本轮最大收获）
- 旧实验 `two_level_tiling_verify.md` 只放大 Q 方向（KV 仍 128、V 未省搬运），得 2406us/1.0x，据此误判「两级分块单独无收益、提速全靠流水」。
- 本轮做的是 **Q+KV 双向真两级**（K/V 都只搬一次），实测 **1.49x**，证明**两级分块本身就有 ~1.5x 实质收益**；流水是在此之上把性能进一步推到 ~4x。
- 盲实现把变量隔离干净（实现者不照搬 main、严格按文档），正是这种隔离暴露并纠正了认知偏差。

## 2. 设计 subagent 复盘
### 成功点
- **算法层面描述到位**：用 `git show 66a35f8` / `git show deae846` 对比两版 kernel，抽取出单一优化点，产出约 400 行算法/伪代码级文档（非源码拷贝），实现者可据此落地。
- **API 事实核实严谨**：核实基线 `matmul_tile.h` **没有** `LoadNzL1ToZnL0BWithTranspose`，并给出 (A) 自补转置 helper / (B) 复用基线裸 `LoadData2D` 两条可选路径（§4.1），让实现者能规避风险。
- **诚实预告风险**：在 §11 显式列出预期收益、根因、5 条主要风险点，没有粉饰。

### 失败点 / 教训
- **沿用旧实验结论，误判收益方向**：设计 subagent 读了 `two_level_tiling_verify.md`，在 §0.2 / §11.1 / §11.2 预告「不带流水的两级分块收益接近 0（~1.0x）」。但旧实验是「**仅 Q 单向**」，本轮设计的是「**Q+KV 双向**」——设计者把单向负面结论错套到双向设计上，导致 §11 预测（~1.0x）与实测（1.49x）**方向相反**。
- **根因**：引用历史结论时未校验「历史实验的变量范围」是否与本轮设计一致。负面结论的适用边界（仅 Q 单向、V 未省搬运）被忽略了。

## 3. 实现 subagent 复盘
### 成功点
- **严格隔离**：遵守「禁看 main」约束，仅凭 `design_doc.md` + 66a35f8 源码实现，保证了变量隔离的纯净度。
- **一次过**：全新编译一次编过，一次精度通过（REL 9.77e-04，mismatch 0%），无修复迭代。
- **5 处合理自推导**：文档不足处自行补齐且决策合理（详见 §4 清单），均朝「更简单 / 更低风险 / 与基线逐字节一致」方向收敛。

### 可改进点
- 实现者需要自行补齐 5 处文档空白，说明**设计粒度还不够细**——这些空白主要集中在「同步契约」「内存 stride / 寻址」「多方案二选一时的默认选择」三类，恰是盲实现最易出错的高风险面。本轮靠实现者经验补救成功，但这是运气而非保障；下一轮设计文档应主动覆盖。

## 4. 设计文档下一版应明确写出的清单（实现者本轮自行补齐的 5 处）
| # | 实现者自补内容 | 文档下一版应明确 |
|---|----------------|------------------|
| 1 | **Q 在 L1 存放**：文档要求固定 256 行双段；实现改为单段 `dstNzC0Stride=qRowsAlign`，更简单等效。 | 直接给出单段方案与微块寻址公式（`startIndex=mStart/C0+i`、`srcStride=qC0Stride/C0`），不要遗留双段歧义。 |
| 2 | **MM1 K 加载方案**：文档给 (A)/(B) 两条路；实现选 (B) 复用基线裸 `LoadData2D`，规避缺失的 transpose helper。 | 明确推荐 (B) 为默认方案，把 (A) 标为「仅在 (B) 不可行时」，避免实现者二选一时踩坑。 |
| 3 | **nL1Size / KL1_SPLIT 取值**：文档推荐 256；实现取 128（=BLOCK_N）与基线加载逐字节一致以降风险，4× 搬运下降仍由 mBaseSize=512 任务合并达成。 | 说清「搬运下降的收益来自任务合并(mBaseSize)而非 KL1 切分粒度」，并推荐 KL1_SPLIT=BLOCK_N 以对齐基线、降风险。 |
| 4 | **L1 复用同步**：文档没写；实现自补 `MTE1_MTE2` flag（上次 L0 读完才允许 GM 重载覆盖 L1）。 | **必须显式写出单缓冲下复用同一 L1 buffer 的同步契约**：何处 SetFlag、何处 WaitFlag、覆盖前的依赖关系。这是盲实现最易遗漏的正确性陷阱。 |
| 5 | **vec state 缓存 stride**：文档没给 per-slot stride；实现用 `stateStride_=AlignUp(mBaseSize,32)` 按全局行索引寻址，避免 subblock 二分后索引错位。 | 给出 per-slot / per-subblock 的 state 寻址公式与 stride 定义，明确 subblock 二分后的全局行索引映射。 |

> 共性：4 / 5 两类（**同步契约**、**stride/寻址**）是盲实现下必须由文档给定的「契约级」信息，不能依赖实现者补。下一版设计文档应把这两类列为强制章节。

## 5. 对下一轮（引入流水 / double buffer）的建议
1. **不要照搬旧结论，先校验变量范围**：本轮 §11 误判的教训——引用任何历史实验（含本轮）结论前，先确认其变量范围与新设计一致；负面结论尤其要标注适用边界。下一轮谈「流水收益」时，基线应明确是「本轮 1590us 的双向两级版」，而非 2391us 原始基线。
2. **明确同步契约**（最高优先级）：流水 / double buffer 的核心难点就是同步。设计文档必须把 buffer ping-pong 的 SetFlag/WaitFlag 时序、跨流水线（MTE2/MTE1/M/FIX/Vec）依赖、CrossCore flag 全部写成显式契约，不能留给实现者补——本轮已证明同步是盲实现最大盲区。
3. **明确 buffer 深度与 L1/UB 重新核算**：引入 double buffer 后 L1 / L0 / UB 占用翻倍，须重新核算是否溢出（L1 容量、UB 192KB、`vec1ChunkRows_` 行切分）。文档应给出每级 buffer 的尺寸表与深度（2 缓冲）下的总占用校验。
4. **保留并复用本轮已验证的两级结构**：两级分块是流水的结构前提（已落地、已验证 1.49x）。下一轮在其上叠加流水，应明确「哪些保持不变、哪些改为多缓冲」，避免推倒重来。
5. **延续盲实现 + 变量隔离范式**：本轮证明该范式能纠正认知偏差、保证收益归因干净。下一轮继续「设计 subagent 写契约 → 实现 subagent 盲实现 → 主控复核」闭环。
