# Attention 详细设计说明书模板

这份模板是 attention / FA 详设正文的结构基线。它不是用来凑章节的，而是用来逼着每一章写到可以实现。

## 一、设计输入与约束

这一节要把设计边界一次性定死。至少要包含：

### 1.1 算子语义

- 这是什么算子
- 主路径到底在算什么
- 输出的语义是什么
- 有没有前处理 / 主处理 / 后处理

### 1.2 接口约束

- proto 输入 / 输出 / attrs / params
- 支持的 dtype
- 支持的 layout
- 非连续输入是否支持
- 是否需要 workspace / stride / offset / index 透传

## 二、详细设计

这是正文主体。这里的每个子章节都要写到能直接指导实现。

### 2.1 主路径和阶段拆解

这一节必须给出阶段表。

#### 必写内容
- 阶段编号和名称
- 阶段执行核
- 输入来源
- 输出去向
- 所属 buffer
- 依赖关系
- 是否主路径
- 是否会被特殊分支替换

#### 推荐表格

| 阶段 | 核 | 输入 | 输出 | buffer | 依赖 | 备注 |
|---|---|---|---|---|---|---|

#### 这一节的常见错误
- 只写阶段名不写输入输出
- 不写 AIC / AIV
- 不写 buffer
- 不写依赖关系

### 2.2 分核与职责

这一节必须回答“谁负责哪段”。

#### 必写内容
- 切分轴是什么，数据如何进行切分
- 每核处理量怎么算
- 余量怎么分
- 小张量怎么保护
- 是否需要 FD / 归约

#### 推荐表格

| 核 / 组 | 负责内容 | 切分规则 | 余量策略 | 备注 |
|---|---|---|---|---|

### 2.3 存储与 buffer

这一节必须写清每一层内存放什么，以及为什么这么放。

#### 必写内容
- 基本块BASE_M/N/K大小是多少
- L1 / L0 / UB / workspace 各自放什么
- 每层 buffer 大小公式
- buffer 份数为什么是这个值
- 哪些 buffer 常驻
- 哪些 buffer 双缓冲
- 哪些 buffer 轮转

#### 推荐表格

| 层级 | 名称 | 用途 | 大小公式 | 份数 | 常驻 | 备注 |
|---|---|---|---|---|---|---|

#### 这一节必须有的校验
- 总使用量
- 是否超硬件容量
- 如果紧张，怎么减 buffer 或改复用策略

#### Cube 操作参数（仅在有特殊设计决策时写）

通用的 Mmad/Fixpipe/LoadData 参数（m/n/k 对应什么维度、srcStride 怎么算等）是标准用法，**不需要在详设中逐项列出**。只有以下特殊情况才需要写：

- 输入分多段（如 prefix + tail）的合并策略：分段 Mmad 累加还是拼接后一次算
- 非标准的 cmatrixInitVal 使用（如首次 true 后续 false 的累加模式）
- 非标准的 L1→L0 搬运模式

### 2.4 各阶段数据流详设

这一节是详设的核心章节，按 C/V 阶段逐一展开每个阶段的完整数据流。

**阶段命名规范**：用 C（Cube 阶段）和 V（Vector 阶段）编号，按流水顺序排列。经典 FA 流水为 `V0 → C1 → V1 → C2 → V2`，其中：
- V0/VG：gather/sink 等数据加载阶段（在第一个 Cube 之前）
- C1：BMM1 等 Cube 阶段
- V1：Softmax 等 Vector 阶段
- C2：BMM2 等 Cube 阶段
- V2：Merge/Output 等 Vector 阶段

#### 每个阶段必须写清

1. **搬运方式和地址公式**：数据从哪来、到哪去、用什么指令、地址怎么算
2. **AIV 任务划分**（MIX 模式下）：vid=0/1 各处理什么
3. **核内同步**：该阶段内所有 SetWaitFlag<HardEvent::XXX> 的位置和语义
4. **跨核同步触发点**：哪个步骤完成后调用 ProducerRelease / ConsumerAcquire
5. **性能要点**（如有）：该阶段的瓶颈或特殊考量

#### 这一节的底线
- 不许只写”搬运到 UB”或”搬运到 L1”
- 不许只写”支持稀疏/PA/sink”而不写具体搬运指令和地址映射
- 不许不写地址公式或索引映射
- 数据加载阶段必须写到搬运指令粒度（DataCopy/LoadNdGmToNzL1/LoadData）
- 不许把同步单独拎到别的章节，必须跟在对应阶段后面写

### 2.5 流水总览与跨核同步

这一节只写两件事：流水全貌和 WorkspaceQueue 表格。核内同步已在 2.4 各阶段中写清，不重复。

#### 流水总览

用 ASCII 图展示一轮计算的阶段划分和 AIC/AIV 交替关系：

```
AIV: [V0 Gather] ──────────────────────────────────────────────
AIC:              [LoadQ] [C1 BMM1]              [C2 BMM2]
AIV:                       [V1 Softmax]          [V2 Merge+Out]
```

#### WorkspaceQueue 表格

跨核同步必须使用 WorkspaceQueue 模式，不写裸 API。用表格列出所有 Queue：

| WorkspaceQueue | slotSize | notifyId | 生产者 | 消费者 | 语义 |
|---|---|---|---|---|---|
| kvQueue | BLOCK_M*(D+tail_dim) | 0 | V0 Gather | C1 BMM1 | workspace_kv 就绪 |
| sQueue | H*BLOCK_M | 1 | C1 BMM1 | V1 Softmax | workspace_s 就绪 |
| pQueue | H*BLOCK_M | 2 | V1 Softmax | C2 BMM2 | workspace_p 就绪 |
| oQueue | H*dimAlign | 3 | C2 BMM2 | V2 Merge | workspace_o 就绪 |

**slotSize**：必须给出具体公式（如 `BLOCK_M * (D + tail_dim)`），不能只写变量名。
**notifyId**：0, 1, 2... 递增分配，避免与 AscendC 内部信号冲突。

### 2.6 尾块与 padding

这一节必须写清尾块的收口方式。

#### 必写内容
- 尾块在哪一层处理
- 外部 shape 是否保持原样
- 冗余数据怎么处理
- 哪些地方要 pad，哪些地方不能 pad
- 尾块是否影响 buffer 份数或同步

### 2.7 特殊分支

这一节必须把所有特殊路径接到主路径上。

#### 必写内容
- sink / page / sparse / GQA / MLA / mask 的触发条件
- 每个分支落在哪个 stage
- 分支如何与主路径衔接
- 哪些分支明确不适用

#### 推荐写法

| 分支 | 触发条件 | 所在 stage | 对主路径影响 | 备注 |
|---|---|---|---|---|

### 2.8 Host / pybind / tiling 契约

这一节必须让实现者知道要透传什么。

#### 必写内容
- 需要透传哪些 shape / stride / offset / index / attr
- tiling 结构需要哪些字段
- workspace 需要多大
- dtype 分发怎么做

### 2.9 性能链

这一节必须写清性能瓶颈在哪里。

#### 必写内容
- 主要瓶颈是什么
- 哪个 buffer / 同步 / 阶段最可能拖慢
- 双缓冲 / 常驻 / 预加载的收益是什么
- 哪些 case 最容易暴露性能问题

## 行数控制

详设正文控制在 **300-500 行**。超出则说明有流水账代码或冗余描述需要精简。

## 反例

下面这些写法都不合格：
- “使用双缓冲””考虑同步”这种无结论的话
- “其余部分与基座一致”这种模糊话
- 只列目录不写内容
- 把实现代码塞进详设
- 把 pattern 当结论替代品
- 在详设中写 TileLang 代码（所有伪码/代码必须使用 AscendC 风格或纯伪码）
- **堆砌流水账式的 AscendC API 调用**（如逐行写 DataCopy/Mmad/SetFlag 调用序列）
- **用代码片段代替设计描述**（如把整个搬运循环展开写成代码块）
- **超过 5 行的连续 AscendC 代码**（设计文档应写决策和参数，不是实现代码）
