# FA-01: 三深任务缓存与四级流水 (Triple-Task Cache & 4-Stage Pipeline)

## Overview

FA类算子的核心性能设计：通过3个RunInfo环形缓冲实现AIC(Cube)和AIV(Vector)的四级流水重叠。每个时钟周期内，AIC执行当前任务的BMM1、上一轮任务的BMM2，AIV执行上一轮任务的Vec1(Softmax)、上两轮任务的Vec2(Update)。这种设计使得Cube和Vector计算单元几乎100%利用，消除了串行等待。

## When to Use

- Cube-Vector双核分离的FA类算子
- 计算流程包含 BMM1 → Softmax → BMM2 → Update 四个阶段
- S2方向有多次循环迭代（s2LoopTimes > 3 时效果最佳）

## Trade-off

- 需要额外2个任务的RunInfo存储空间
- 流水启动和排空阶段（各2轮）存在气泡
- 跨核同步flag数量增加（至少4个CrossCore flag）
- 调试复杂度高，时序问题难以定位

**Source operators**: fused_infer_attention_sink, sparse_flash_attention_gqa, sparse_flash_attention_pioneer

## Variant A: 标准四级流水（GQA/Sink）

Source: sparse_flash_attention_gqa, fused_infer_attention_sink

两个算子采用相同的四级流水编排：BMM1 → Vec1(Softmax) → BMM2 → Vec2(Update)。通过 `SFA_PRELOAD_TASK_CACHE_SIZE = 3` 的环形缓冲，实现三个任务在流水线中同时执行。

**核心编排逻辑**（`kernel_nonquant.h:863-889`）：
```cpp
static constexpr uint32_t SFA_PRELOAD_TASK_CACHE_SIZE = 3;

ExecuteTask(loop, extraInfo[3]):
  extraInfo0 = extraInfo[loop % 3]       // 本轮任务
  extraInfo2 = extraInfo[(loop + 2) % 3] // 上一轮任务
  extraInfo1 = extraInfo[(loop + 1) % 3] // 上两轮任务

  AIC: ComputeMm1(extraInfo0)     // 当前任务做BMM1
  AIV: ComputeVec1(extraInfo2)    // 上一轮任务做Softmax
  AIC: ComputeMm2(extraInfo2)     // 上一轮任务做BMM2
  AIV: ComputeVec2(extraInfo1)    // 上两轮任务做Update
```

**跨核同步拓扑**：
```
AIC:  ──BMM1[0]──┐                    ┌──BMM2[0]──┐
                  │ syncC1V1           │           │ syncC2V2
                  ↓                    │           ↓
AIV:            Vec1[0](Softmax)───────┘         Vec2[0](Update)
                      │ syncV1C2
                      └──→ AIC等待后开始BMM2
```

**同步Flag定义**：
```cpp
SYNC_C1_V1_FLAG = 7    // Cube1(BMM1完成) → Vec1(开始Softmax)
SYNC_V1_C2_FLAG = 8    // Vec1(Softmax完成) → Cube2(开始BMM2)
SYNC_C2_V2_FLAG = 9    // Cube2(BMM2完成) → Vec2(开始Update)
```

**流水时序图**：
```
Loop:    0        1              2              3
AIC:  BMM1[0]   BMM1[1]      BMM1[2]+BMM2[0]  BMM1[3]+BMM2[1]
AIV:             (空)         Vec1[0]          Vec1[1]+Vec2[0]
```

Benefit: Cube和Vector计算单元近100%利用率，消除串行等待，理论加速比接近2x
Trade-off: 流水启动排空各2轮气泡；需要4个CrossCore同步flag

## Variant B: 五级流水 + Vec0 KV合并（Pioneer）

Source: sparse_flash_attention_pioneer

Pioneer在标准四级流水基础上增加了Vec0阶段（KV合并/TopK过滤），形成五级流水。Vec0在AIV核上执行，将稀疏TopK索引对应的KV块合并到连续workspace中，供后续BMM1使用。

**核心编排逻辑**（`kernel_mla.h:857-899`）：
```cpp
PreloadPipeline(loop, ...):
  extraInfo0 = extraInfo[loop % 3]       // 本轮任务
  extraInfo2 = extraInfo[(loop + 2) % 3] // 上一轮任务
  extraInfo1 = extraInfo[(loop + 1) % 3] // 上两轮任务

  // 本轮：AIC做BMM1，AIV做Vec0(KV合并)
  if (extraInfo0.isValid) {
      if ASCEND_IS_AIC {
          CrossCoreWaitFlag(syncV0C1);  // 等待Vec0完成KV合并
          ComputeMm1(extraInfo0);
      } else {
          CrossCoreWaitFlag(3);          // 等待AIC释放workspace
          vectorService.MergeKv(extraInfo0);  // Vec0: KV合并
          CrossCoreSetFlag(syncV0C1);    // 通知AIC可以开始BMM1
      }
  }
  // 上一轮：AIV做Vec1(Softmax)，AIC做BMM2
  if (extraInfo2.isValid) {
      if ASCEND_IS_AIV { vectorService.ProcessVec1L(extraInfo2); }
      if ASCEND_IS_AIC {
          ComputeMm2(extraInfo2);
          CrossCoreSetFlag(3);           // 通知AIV可以开始下一轮Vec0
      }
  }
  // 上两轮：AIV做Vec2(Update)
  if (extraInfo1.isValid) {
      if ASCEND_IS_AIV { vectorService.ProcessVec2L(extraInfo1); }
  }
```

**新增同步点**：
```cpp
SYNC_V0_C1_FLAG = 6    // Vec0(KV合并完成) → Cube1(开始BMM1)
// + 额外使用flag 3实现AIC→AIV的反向通知（BMM2完成后AIV可开始下一轮Vec0）
```

**与Variant A的关键区别**：
1. 新增Vec0阶段，AIC需要等待Vec0完成才能开始BMM1
2. AIC完成BMM2后需要反向通知AIV（flag 3），形成双向同步
3. Vec0的KV合并写入独立的kvMergeGm workspace区域

Benefit: 稀疏场景下通过TopK过滤减少BMM1计算量；KV合并与BMM2并行执行
Trade-off: 新增Vec0阶段引入额外同步开销；需要额外的kvMerge workspace空间

## Variant C: M轴NBuffer二次切分（Pioneer）

Source: sparse_flash_attention_pioneer

当mBaseSize较大时（如MLA场景gSize可能>256），Pioneer对M轴进行二次切分，每次处理 `N_BUFFER_M_BASIC_SIZE=256` 行，确保L0容量不溢出。

```cpp
// kernel_mla.h:734-746
void ComputeMm1(const RunInfo &info) {
    uint32_t nBufferLoopTimes = (info.actMBaseSize + constInfo.nBufferMBaseSize - 1)
                                / constInfo.nBufferMBaseSize;
    uint32_t nBufferTail = info.actMBaseSize - (nBufferLoopTimes - 1) * constInfo.nBufferMBaseSize;
    for (uint32_t i = 0; i < nBufferLoopTimes; i++) {
        MSplitInfo mSplitInfo;
        mSplitInfo.nBufferStartM = i * constInfo.nBufferMBaseSize;
        mSplitInfo.nBufferDealM = (i + 1 != nBufferLoopTimes) ? constInfo.nBufferMBaseSize : nBufferTail;
        matmulService.ComputeMm1(info, mSplitInfo);
        CrossCoreSetFlag(syncC1V1);  // 每个M子块完成后都通知Vec1
    }
}
```

**vs. GQA/Sink（无二次切分）**：
```cpp
// GQA/Sink: mBaseSize由Tiling分档控制，保证不超过L0容量
// 不需要M轴二次切分
ComputeMm1(info):
    matmulService.ComputeMm1(info)
    CrossCoreSetFlag(syncC1V1)  // 整个M块完成后通知
```

Benefit: 支持更大的mBaseSize（MLA场景gSize可达数百），不受L0容量限制
Trade-off: 每个M子块都需要一次CrossCore同步，增加同步开销
