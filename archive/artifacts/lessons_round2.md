# 第二轮经验教训复盘（lessons_round2.md）

> 实验范式：设计 subagent（可参考 main HEAD）写设计文档 → 实现 subagent（禁看 main）仅凭文档盲实现 → 主控复核性能 → 无收益则循环。
> 本文复盘第二轮，并把改进点反向沉淀给第三轮。

## 0. 本轮目标与结果（一句话）
在第一轮 6fc58de（双向两级分块、单缓冲、1590us）上**独立**叠加「多缓冲 + PRELAUNCH 软流水 + 删手工 barrier」单一增量，盲实现一次编过、精度 PASS、**无死锁**，性能 **1590us → 977us（相对第一轮 1.63x，相对原始 2391us 2.41x）**。

## 1. 关键认知确认（本轮最大价值）
- 第二轮以干净的隔离实验证明：**流水（搬运-计算重叠）与两级分块（省搬运）是正交维度，可乘性叠加**——1.49x（第一轮）× 1.63x（本轮）≈ 2.41x。
- 这彻底推翻了历史 `two_level_tiling_verify.md` 时期的「提速全靠流水、两级分块无收益」单因论：两个优化各自贡献约 1.5–1.6x，缺一不可。
- 第一轮 lessons §5.1 的告诫（不照搬历史结论、基线锚定 1590us 而非 2391us）被设计 subagent 正确执行，本轮预期收益区间（605~800us）与实测 977us 方向一致、未再出现第一轮 §11 那种方向性误判。

## 2. 设计 subagent 复盘
### 成功点（相对第一轮的进步，均源自 lessons_round1 §5 建议）
- **基线锚定正确**：开篇即声明「收益相对 1590us 评估，绝不锚定 2391us」，并多处引用 lessons_round1 的误判教训作为反面教材。第一轮的方向性误判未重演。
- **同步契约写成强制章节**（lessons_round1 §5.2 的最高优先级建议被落实）：§4 分三层（A 跨核 CrossCore flag / B Cube L1/L0 TQue 自动同步 / C Vec UB 队列）逐层给出显式契约，含生产者-消费者依赖图、flag 配对不变量（Acquire/Release 各累计 s2OuterBlocks 次、prologue 只 Producer、epilogue 只 Consumer）、vecDealM==0 必须补发 P_READY、PIPE_M 累加序 vs 跨流水 flag 的区分。
- **buffer 尺寸表与容量校验**（lessons_round1 §5.3 建议被落实）：§5 给出 L1=416KB、L0C 深度2=128KB 恰满、UB≈190KB 三张表，并标注逼近上限的退化方案（outputQue1_ 退回深度1）。
- **范围声明清晰**：§0 明确「改什么/不改什么」，把第一轮已验证的两级结构列为禁止重构的前提，只抽取流水单一增量——保持了单变量隔离。

### 失败点 / 教训
- **未达成 605us 目标（达成约 62%）**：设计 subagent 把 605us 当作「可达上界」（§8.1 称「605us 是 main 相对第一轮的唯一增量，故可达」），但实际只到 977us。
- **根因**：设计文档为隔离变量**刻意保留第一轮的 MM1 裸 LoadData2D（方案B）**，没引入 main 的转置加载路径（§6 末尾明确「不引入 main 转置路径」）。即本轮抽取的并非「main 相对第一轮的全部增量」，而只是其中的「流水+多缓冲」子集——「MM1 转置加载」是 main 的另一个独立增量，被本轮主动排除。设计 subagent 在 §8.1 把「流水增量」等同于「main 全部增量」，高估了可达上界。
- **次要因素**：§8.1 已诚实预告 s2OuterBlocks=2 偏小会稀释 prologue/epilogue 收益（保守区间 700~800us），实测 977us 甚至略低于该保守区间下沿，说明流水填充/排空开销 + 未省的转置加载开销叠加比预期更显著。

## 3. 实现 subagent 复盘
### 成功点
- **同步零失误**：第一轮最大盲区（同步契约靠实现者自补）本轮因 §4 写明而被彻底规避——一次编过、一次精度过、**无死锁、无 buffer 溢出**（L0C 128KB 恰满、UB outputQue1_ 深度2 未溢出，退化方案未动用）。这直接验证了 lessons_round1 §5.2「同步契约必须由文档给定、不能留给实现者补」的有效性。
- **严格隔离**：遵守「禁看 main」，仅凭 design_doc_round2.md + 6fc58de 源码实现，保证变量隔离纯净。
- **最小改动边界**：严格按 §6 只动 cube/vec/kernel 三个文件，tiling/workspace_queue/matmul_tile 未碰，收益归因干净。

### 可改进点
- 本轮实现 subagent 几乎无自推导空白（对比第一轮的 5 处），说明设计文档细化已到位——这本身是正向信号，但也意味着**收益上限被设计文档的「范围声明」锁死**：实现者严格不越界，所以设计排除转置加载，实测就拿不到那部分收益。结论：当文档足够细时，收益天花板完全由设计 subagent 的「抽取哪些增量」决定。

## 5. 对第三轮（逼近 605us）的建议
1. **正面抽取被本轮排除的增量**：977us→605us 的差距主因是本轮刻意排除的 **MM1 转置加载路径**（main 的 `LoadNzL1ToZnL0BWithTranspose`）。第三轮设计应正面评估：实现方案A（自补转置 helper）的收益与风险，这是回收剩余差距的最大单点。
2. **诚实区分「单增量上界」与「累计上界」**：第三轮设计谈收益时，基线应锚定**第二轮 977us**，目标 605us 的差距要拆成「转置加载」「s2OuterBlocks 调大提高 steady 占比」等可独立验证的子项，不要再把「某单一增量」等同于「main 全部剩余增量」。
3. **延续已落实的强制章节**：§4 同步契约、§5 buffer 容量表是本轮零失误的关键，第三轮若动 L0B 加载方式（转置）会改变 L0B 的 stride/寻址，必须把转置 helper 的 LoadData2DParams（C0 分块循环的 src/dst 偏移、repeatTimes、ifTranspose）写成契约级伪代码，避免实现者在最易错的 stride 上踩坑（呼应 lessons_round1 §4 的 stride/寻址类盲区）。
4. **保留单变量隔离**：第三轮只抽取「转置加载」（或「调大 s2BaseSize」二选一，建议先转置加载因其是差距主因），不要同时改多点，保持收益归因干净、可与第二轮 977us 直接对比。
5. **延续盲实现 + 主控复核闭环**：两轮已证明该范式稳定产出乘性收益且能纠偏，第三轮继续。
