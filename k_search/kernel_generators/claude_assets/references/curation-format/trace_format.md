# Trace.md 格式规范

结构化执行记录，记录本次任务各阶段的执行情况。

## 格式模板

```markdown
# Trace: {算子名称}

- 时间: {当前日期时间}
- 算子: {current_task 对应的算子名}
- 最终结果: PASS / FAIL (tilelang) | PASS / FAIL (ascendc)

## 阶段零: 用例设计与生成

- 结果: 通过 / 失败 / 跳过
- 基础 case 数: {n}
- 泛化 case 数: {n}
- 备注: {如有异常情况}

## 阶段一: TileLang

- 结果: 通过 / 失败
- evaluate_tilelang.sh 执行次数: {n}
- 关键错误信息: {评测脚本返回的错误，原文引用}
- 知识事件来源: current_task/artifacts/ / 缺失 / 为空
- Agent 行为记录:
  - 第 1 轮: {agent 做了什么，结果如何}
  - 第 2 轮: {修改了什么，结果如何}
  - ...
- 走偏点: {agent 做了哪些无效/错误/冗余的尝试，以及可能的原因}

## 阶段二: AscendC 详细设计

- 结果: 通过 / 失败 / 跳过
- 设计文档: `current_task/artifacts/ascendc_design.md` / 缺失
- 关键设计决策:
  - {例如：MIX kernel / 主路径分段 / workspace 方案 / 同步机制选择}
- 备注: {是否覆盖 tail / mask / GQA / page / sparse 等特殊分支}

## 阶段三: AscendC

- 结果: 通过 / 失败
- evaluate_ascendc.sh 执行次数: {n}
- 关键错误信息: {评测脚本返回的错误，原文引用}
- 知识事件来源: current_task/artifacts/ / 缺失 / 为空
- Agent 行为记录:
  - 第 1 轮: {agent 做了什么，结果如何}
  - 第 2 轮: {修改了什么，结果如何}
  - ...
- 重型调试摘要（如有 debug trace）:
  - 迭代 1: {操作、结果、分析、状态}
  - 迭代 2: {...}
- 走偏点: {agent 做了哪些无效/错误/冗余的尝试，以及可能的原因}

## 阶段四: 全量用例验证

- 结果: {通过 / 失败 / 跳过}
  - 迭代 1: {操作、结果、分析、状态}
  - 迭代 2: {...}

## 阶段五: 性能数据采集与调优

- 结果: {执行 / 未执行 / 跳过}

## 评测输出摘要

{粘贴最后一次 evaluate 脚本的关键输出片段，包括 PASS/FAIL 状态和错误详情}
```

## 记录原则

1. **精确引用**: 错误信息、评测输出使用原文，不要改写或总结
2. **行为序列**: 每轮迭代记录 agent 的实际操作（改了什么文件、改了什么逻辑），而非笼统的"修复了 bug"
3. **走偏分析**: 重点记录 agent 做了哪些最终被证明无效的尝试
4. **省略成功**: 如果某阶段一次通过且无异常，简要记录即可，不需要展开
